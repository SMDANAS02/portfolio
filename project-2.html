Smart Meal Notification

A nutrition-tracking API built around one idea: your calorie target shouldn't be static — it should adapt to what you actually ate yesterday.

Node.jsExpressMySQL JWT · bcryptNodemailer
GitHub Repo Ask about it
the problem

Fixed calorie targets don't reflect real life.

Most nutrition trackers set one static daily target and leave it there, ignoring the fact that overeating on Monday should reasonably change your Tuesday. That mismatch is a big reason people abandon tracking apps within weeks.

what I built

A RESTful API with a "Calorie Debt" engine.

  • A normalized MySQL schema for users, meals, and progress logs, designed to keep nutrition history queryable and consistent.
  • A Calorie Debt algorithm that dynamically recalculates each day's target based on historical overages, so adherence stays realistic instead of punishing.
  • Secure authentication using JWT and bcryptjs, with route-level guards on every nutrition and progress endpoint.
  • Automated meal reminders and progress notifications via Nodemailer, so the system nudges users instead of waiting to be opened.
why it matters

Behavior-aware, not just data-aware.

The interesting part of this build wasn't the CRUD — it was encoding a behavioral rule (debt-adjusted targets) directly into the backend logic, so the API itself nudges users toward sustainable habits rather than rigid numbers.
